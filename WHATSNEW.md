# Что нового в NetKnownsThat

Короткие заметки к каждой версии — то, что видит пользователь, а не
перечень коммитов (тот в [CHANGELOG.md](CHANGELOG.md)). Новое сверху.

Раздел добавляется тем же коммитом, что и бамп файла `VERSION`, и
заголовок пишется с `v` — ровно так, как называется тег релиза. При
выпуске тега `.github/workflows/release.yml` собирает описание GitHub
Release из разделов, накопившихся с прошлого тега, а хаб показывает это
описание в разделе «О системе», когда появляется новая версия.

## v1.9.64 — 2026-09-12

- «О системе» на хабе: кнопка «Проверить» (была «Проверить снова») и
  новая «Откатить на <версия>» — ставит релиз, идущий сразу перед
  текущим: скачивает бинарник и юнит, сверяет контрольную сумму,
  перезапускается. Проверка версии теперь читает список релизов, а не
  только последний, и показывает предыдущую версию рядом с текущей.
- Хост с версией, отличной от хаба в любую сторону, приводится к версии
  хаба: после отката хаба такой хост при «открыть» сначала
  переустанавливается (как и отставший), «обновить всё» считает и его,
  в строке действие называется «привести к версии хаба».

## v1.9.63 — 2026-09-12

- Английский интерфейс без русских вставок: все сообщения с сервера —
  ошибки API, строки журналов заданий, шаги заданий, заметки в сводках
  («нет lm-sensors…», «timedatectl недоступен…»), подписи карты
  ресурсов, описания хода сканирования — теперь приходят на языке
  интерфейса. Язык задания фиксируется при запуске: журнал пишется на
  языке того, кто его запустил, и таким остаётся.
- Запасной язык интерфейса — английский: если какого-то ключа перевода
  вдруг нет, англоязычный пользователь не увидит русскую строку.

## v1.9.62 — 2026-09-12

- Заготовки конфигураций под сертификат (nginx, haproxy, caddy) теперь
  отдают статику из стандартного /var/www/html (у nginx — с привычным
  `index index.html index.htm index.nginx-debian.html`), а прокси на
  приложение (`proxy_pass`, `reverse_proxy`, `server app1`) оставлен
  закомментированным примером.

## v1.9.61 — 2026-09-12

- Проводник: у файла действие «Изменить» открывает редактор — имя файла
  наверху (поменяли — файл переедет), текст с номерами строк, права
  сохраняются, а если файл за это время правил кто-то ещё, запись
  отклоняется вместо затирания. Двоичные и файлы больше 2 МиБ — только
  скачать.
- «Системные настройки» → «Локали»: все известные системе локали
  ячейками, как пакеты, с поиском; видно, какие сгенерированы и какая
  основная; отмеченные генерируются (locale.gen + locale-gen), любую
  сгенерированную можно сделать основной (update-locale / localectl).
- «Системные настройки» → «Синхронизация времени»: какая служба стоит
  (systemd-timesyncd, chrony, ntpsec), с кем сверяется, stratum и
  расхождение; выбор серверов NTP из списка или своих (drop-in службы);
  «Синхронизировать сейчас»; если службы нет — установка systemd-timesyncd
  с живым журналом apt.

## v1.9.60 — 2026-09-12

- В проводнике можно загружать целые папки: кнопкой «Папку» (диалог
  выбора папки) или перетаскиванием файлов и папок из проводника ОС прямо
  в таблицу. Дерево каталогов повторяется на хосте, файлы идут по три
  разом, прогресс — один общий: «N из M файлов», ошибки по отдельным
  файлам списком. Пустые папки браузер не отдаёт — это его ограничение.

## v1.9.59 — 2026-09-12

- Загрузке и скачиванию файлов через проводник даётся 5 минут — и на
  хосте, и в прокси хаба — вместо общих 2 минут на запрос и 30 секунд на
  чтение тела: большой файл по медленному каналу больше не обрывается.
- Исправлена сборка на 32-битных платформах (потолок загрузки 2 ГиБ не
  помещался в int).

## v1.9.58 — 2026-09-12

- «Диски» → «Файлы»: проводник по каталогам хоста. Ходить по папкам,
  создавать их, переименовывать и удалять, скачивать файлы, загружать
  через окно выбора файлов (с полосой прогресса по каждому), распаковывать
  архивы zip/tar прямо на месте. Только внутри разрешённых корней — по
  умолчанию /home, /srv, /opt, /var/www и /tmp (`NKT_FILES_ROOTS`).
- Там же — `git clone` заданием с журналом. Приватные репозитории: токен
  или пароль по HTTPS (уходит на хост один раз, в базу и журнал не
  попадает) либо deploy-ключ хоста по SSH — публичная половина показана
  для добавления в GitHub/GitLab.

## v1.9.57 — 2026-09-12

- «+ N» у хоста переехал в его строку, перед «открыть»: только знак и
  число, ровно три знакоместа — у хоста без машин пустых, чтобы иконки во
  всех строках начинались в одном месте. Строка с машинами раскрывается
  только по нажатию.

## v1.9.56 — 2026-09-12

- «Найти машины на хосте»: окно показывает ход поиска, после «добавить»
  остаётся открытым и убирает добавленные из списка, а не падало с
  «Cannot read properties of null».
- У работающей машины снова видна кнопка «открыть», даже если опрос
  хоста ещё не успел заметить, что домен запущен: если хаб достучался до
  nkt внутри, машина работает.

## v1.9.55 — 2026-09-12

- У хоста в списке хаба появилась кнопка «найти машины на хосте»: домены
  libvirt, созданные не через nkt, показываются с состоянием и адресом,
  выбранные заводятся машинами этого хоста — с паролем SSH (тогда nkt
  можно ставить сразу) или с ключом хаба, который кладут в машину руками.
  У выключенной машины адрес определится после запуска.

## v1.9.54 — 2026-09-12

- У машины в списке хостов «старт» и «выключить» относятся к самой
  машине и идут через хост, на котором она создана (libvirt), а не по SSH
  внутрь: выключенной машине по SSH было некуда стучаться. После старта
  адрес определяется сам. В строке видно состояние домена; у выключенной
  остаются только «запустить машину», «изменить» и «удалить».
- В «Оповещениях» появились настройки: какие события записывать в
  журнал и о каких уведомлять всплывающим, плюс сворачивание коротких
  эпизодов — «не отвечает» и «снова отвечает» в пределах N минут
  становятся одной строкой «был недоступен N мин».

## v1.9.53 — 2026-09-12

- «Новый файл» в «Конфигурациях» начинается с корня выбранной категории
  (nginx → /etc/nginx, docker → /home или /srv/compose) и ведёт только
  вглубь: дерево каталогов, создание папки, имя файла — а выше корня
  хода нет. Клонирование открывается в каталоге исходного файла.

## v1.9.52 — 2026-09-12

- «Выключить автозапуск» у службы с SysV-скриптом (haproxy и подобные)
  больше не падает с «update-rc.d: Read-only file system»: enable/disable
  выполняются вне песочницы юнита.
- Имя хоста в списке хаба — ровно десять знаков в ширину: действия у всех
  строк начинаются в одном месте.

## v1.9.51 — 2026-09-12

- Список хостов стал ровнее: состояние — первой колонкой одной иконкой
  (слово и текст ошибки — в подсказке), имя не длиннее десяти знаков
  (целиком — в подсказке), у localhost в адресе просто «—», а без sudo
  NOPASSWD в колонке стоят два красных крестика той же ширины, что
  галочка с кнопкой «снять», — колонки больше не прыгают между строками.

## v1.9.50 — 2026-09-12

- В «Неподключённых сертификатах» у каждой строки — кнопки nginx,
  haproxy и caddy: готовый фрагмент конфигурации именно с этим
  сертификатом (пути lineage и все имена из него подставлены, указано,
  в какой файл его обычно кладут) и одна кнопка «Скопировать». У haproxy
  — напоминание про склеенный PEM, который собирает форма ниже.

## v1.9.49 — 2026-09-12

- Выпущенный сертификат виден сразу после завершения задания — раньше он
  появлялся в «Неподключённых» только после повторного входа в раздел.
- В списке хостов «снять sudo NOPASSWD» стоит рядом с галочкой в колонке
  «Sudo» — там, к чему она относится, а не среди общих действий.

## v1.9.48 — 2026-09-12

- «Сертификаты» проверяют certbot при входе: если его нет — плашка с
  кнопкой «Установить certbot» (ставится вместе с плагином nginx), после
  установки хост пересканируется сам. Отсутствие каталога certbot больше
  не показывается как ошибка запроса, а «выпустить» без certbot не
  падает на запуске — кнопка заблокирована с подсказкой.
- Перед выпуском и продлением через --standalone показывается, кто
  держит порты 80/443, и что с ним будет: служба systemd будет
  остановлена и запущена обратно; процесс, запущенный руками (Flask,
  gunicorn, свой сервер), — по галочке остановлен и поднят заново той
  же командой, в том же каталоге, под тем же пользователем и с тем же
  окружением, команда видна до подтверждения; контейнер или нечитаемый
  процесс nkt не трогает — порт освобождают сами. Список nginx/haproxy
  «по памяти» больше не используется.

## v1.9.47 — 2026-09-12

- Проверка порта доросла до полноценного инструмента: ответ можно
  отрисовать (HTML — в песочнице без скриптов и сети, картинку, JSON с
  отступами, PDF), посмотреть текстом или hex-дампом и скачать; у
  запроса — любой метод (включая свой), заголовки, тело с типом
  (текст, JSON с проверкой, форма, XML). TCP и TLS читают баннер
  сервера и умеют послать строку и дождаться ответа — как nc. Появился
  вид «curl со своими параметрами»: настоящий curl на хосте, аргументы
  разбираются без оболочки.
- «Пакеты»: и поиск, и установленные показаны ячейками в несколько
  колонок, а не по одному в строку; фильтр установленных сортирует и
  раскрашивает совпадения так же, как поиск.

## v1.9.46 — 2026-09-12

- Рядом с каждым слушающим портом — в «Остальных сервисах», в
  фаерволе и у опубликованных портов Docker — иконка проверки. Окно
  предлагает соединиться, спросить по HTTP/HTTPS (метод, путь, заголовок
  Host, без проверки сертификата) или посмотреть TLS-сертификат, с
  таймаутом на выбор. Проверяет сам nkt, curl на хосте не нужен, а
  эквивалентная команда (curl, nc, openssl) показывается для терминала.
  Через хаб есть вторая кнопка — проверить с хаба, то есть снаружи,
  через фаервол. Проверять можно только адреса самого хоста.
- «Пакеты»: поиск и установленные показаны одинаковыми компактными
  таблицами — галочки, имя со значком ⓘ (описание по наведению вместо
  широкого столбца), версия, действие иконкой. Удалять, как и ставить,
  можно набором — одним apt-get. У установленных появилось описание.

  Строка ниже остаётся только у хостов с машинами: «+ 3» / «− 3», без
  слова «машин».
- «Sudo» и «Канал» в той же таблице — галочкой или крестиком, слово в

- У виртуальных машин автозапуск показан иконкой вкл/выкл, клик по ней

## v1.9.44 — 2026-09-11

- Действия в таблицах стали иконками: запустить, остановить,
  перезапустить, включить автозапуск, править, удалить, журнал и

- Строки таблиц стали заметно ниже: у контейнера пять действий, у службы
  до восьми — словами они занимали больше места, чем всё остальное в

## v1.9.43 — 2026-09-11

- В обзоре появилась карточка «Что изменилось»: сравнение состояния
  хоста с тем, каким его видели в прошлый раз. Порт открылся или
  закрылся, служба остановилась или появилась новая, правился файл
  конфигурации, подменили образ контейнера, сменился адрес интерфейса,
  истёк или обновился сертификат — всё это видно списком, с «было» и
  «стало». Кнопка «принять» сдвигает точку отсчёта.
- Сравнивается отобранный набор фактов, а не сырой снимок: память
  процесса, «Up 8 days» и перестановка правил фаервола изменением не
  считаются, иначе настоящая правка тонула бы в шуме.
- Снимки состояния теперь чистятся: хранятся последние 200.

## v1.9.42 — 2026-09-11

- В хабе появился раздел «Оповещения»: хост перестал отвечать, снова
  ответил, появились или исчезли серьёзные находки. События записывает
  сам хаб при фоновом опросе, поэтому журнал не зависит от открытой
  вкладки, а в каждой строке видно имя хоста и его адрес — те, что были
  на момент события. У раздела в меню счётчик непоказанных.
- Всплывающие уведомления берут текст из того же журнала: в заголовке
  теперь имя и адрес хоста, в теле — что именно случилось. Раньше было
  только имя, а история нигде не сохранялась.
- Журнал задания больше не повторяет последние строки: несколько
  одновременных дочитываний приносили один и тот же хвост, отсюда и три
  «Готово» подряд.
- Таблица Docker стала читаемой: состояние и время в одну строку,
  действия в один ряд, длинная сумма образа показывается началом и
  концом (полная — в подсказке).

## v1.9.41 — 2026-09-11

- «Профили» переехали последней вкладкой в «Контейнеры и ВМ» — туда же,

- У контейнеров Docker появилось действие «удалить». Запущенный

- Виртуальные машины показываются одним списком: остановленные больше не

- Таблицы больше не делят ширину поровну: колонка подстраивается под

## v1.9.40 — 2026-09-11

- В списке хостов «установить/обновить/переустановить» и «определить
  адрес» больше не выбиваются из строки рамкой: это такие же действия,

## v1.9.39 — 2026-09-11

## v1.9.38 — 2026-09-11

- Профиль со стеком compose на хосте без docker больше не обрывается на

## v1.9.37 — 2026-09-11

- Вкладка «Docker» больше не падает с «Cannot read properties of null»:
  образ без тега приходил с `tags: null`, и первый же такой образ ронял
  раздел целиком. Список образов всегда отдаёт массив, а страница
  переживает и пустое значение.
- Заодно проверены все ответы API: пустые списки нигде больше не
  превращаются в `null` — это касалось ещё образов машин и диагностики
  терминала.

## v1.9.36 — 2026-09-11

- В «Профилях» появился знак вопроса у заголовка: он открывает справку по
  формату — что означает каждый раздел, чем «не указано» отличается от

  делает. С примерами и на обоих языках интерфейса.

## v1.9.35 — 2026-09-11

- Профиль умеет разворачивать сервисы из compose-файлов: раздел
  `compose` описывает стек целиком, применение кладёт его на хост,
  проверяет самим `docker compose` и поднимает; `up: false` — опускает.

## v1.8.85 — 2026-09-09

- Хосты: в форме добавления появилась «Подготовка нового хоста» — для
  свежего сервера, где есть только root и пароль. Ставит недостающие
  пакеты (список редактируется), заводит пользователя с sudo без пароля,
  кладёт ключ хаба и переводит хост на вход по ключу, а по желанию гасит
  вход по паролю. Каждый необратимый шаг делается только после того, как
  следующий способ входа проверен новым соединением. Только
  Debian/Ubuntu-подобные системы.

## v1.8.84 — 2026-09-09

## v1.8.83 — 2026-09-09

- Терминал на Debian 13: исправлена ошибка «nsenter: reassociate to
  namespaces failed: Operation not permitted». В util-linux 2.41, которая
  там стоит, nsenter входит в пространство имён через pidfd, а этот вызов
  песочница systemd-юнита отклоняет. Теперь пространство имён указывается
  файлом — так работает на всех версиях util-linux.

## v1.8.82 — 2026-09-08

- Конфигурации: созданный файл больше не исчезает из списка. Раньше в
  списке было только то, до чего дотягивается сама служба через include —
  файл в sites-available пропадал сразу после сохранения, и никакое
  пересканирование не помогало.
- Конфигурации: выбор категории над списком файлов, с количеством в
  каждой; отдельная категория «не подключены» для файлов, лежащих на
  диске, но не участвующих в работе службы.
- Конфигурации: новые категории — юниты systemd, сеть и имена (netplan,
  /etc/hosts, /etc/resolv.conf), sshd, параметры ядра и cron. У каждой
  своя проверка перед сохранением и свой способ применения; сетевую
  конфигурацию nkt намеренно не применяет сам.
- Конфигурации: правка sshd_config требует резервного канала — пути к
  хосту в обход самого sshd. Если его нет, правка блокируется, пока
  оператор явно не подтвердит, что у него есть консоль. После применения
  nkt открывает к sshd новое соединение и, если демон перестал отвечать,
  возвращает конфигурацию к прежнему виду.
