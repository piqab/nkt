# Что нового в NetKnownsThat

Короткие заметки к каждой версии — то, что видит пользователь, а не
перечень коммитов (тот в [CHANGELOG.md](CHANGELOG.md)). Новое сверху.

Раздел добавляется тем же коммитом, что и бамп файла `VERSION`, и
заголовок пишется с `v` — ровно так, как называется тег релиза. При
выпуске тега `.github/workflows/release.yml` собирает описание GitHub
Release из разделов, накопившихся с прошлого тега, а хаб показывает это
описание в разделе «О системе», когда появляется новая версия.
Английская версия каждого раздела — в [WHATSNEW.en.md](WHATSNEW.en.md),
тем же коммитом: workflow приклеивает её к описанию релиза после
маркера `<!-- en -->`, и хаб показывает читающему его язык.

## v1.10.107 — 2026-09-25

## v1.10.106 — 2026-09-25

- **LXD из snap теперь работает из nkt.** После установки LXD список
  образов и инстансы падали с «exec: "lxc": executable file not found in
  $PATH»: snap кладёт `lxc` в `/snap/bin`, которого нет в PATH службы, а
  сама snap-обёртка запускается через setuid-помощник, который в
  песочнице юнита (NoNewPrivileges) не работает. Теперь `/snap/bin` —
  в PATH службы, а `lxc` выполняется вне песочницы по полному пути, как
  `virsh`. Обновите nkt на хосте.

## v1.10.105 — 2026-09-25

- **Прогресс бэкапа и восстановления — полосой.** Окно задания (и
  колонка «Шаг» в «Заданиях») показывает процент текущей операции и что
  сейчас идёт: копирование диска (`qemu-img`), упаковка томов, каталога
  проекта и архива, распаковка при восстановлении (`tar`). Шаги без
  процентов (сохранение образа, `virsh define`) — индикатор занятости с
  названием. Заодно полосу получили все задания с шагами (установка и
  обновление хостов и др.).

## v1.10.104 — 2026-09-25

- **Бэкап машины падал сразу** («unary operator expected», «Option
  argument is empty»): сценарий уходил строкой через systemd-run, а
  systemd сам подставляет `${…}` в аргументах — список дисков и параметры
  снимка доходили пустыми. Теперь сценарий запускается файлом. Машину
  прошлая неудачная попытка не затронула: снимок не был создан.
- **Страховка при сбое бэкапа работающей машины**: если копирование
  упало уже после снимка, изменения всё равно возвращаются в диски
  (`blockcommit`), и машина не остаётся на временных overlay-файлах.

## v1.10.103 — 2026-09-25

- **Бэкап и восстановление машин и контейнеров.** Иконка «бэкап» в
  строке машины libvirt, контейнера Docker и Podman открывает окно:
  список архивов на хосте, «создать бэкап» (фоновое задание с живым
  журналом), скачать (и через хаб), удалить, восстановить — копией под
  новым именем или поверх.
  - **Машина:** XML и диски (сжатый qcow2). Работающая не
    останавливается: диски на время копирования уходят на внешний
    снимок, затем изменения возвращаются (`blockcommit`); с
    qemu-guest-agent снимок согласован. Копия получает новые UUID и MAC.
  - **Контейнер:** образ из текущего состояния (`commit` + `save`),
    параметры запуска и именованные тома. Копия — со своими томами и без
    опубликованных портов.
  - **Compose-стек** (контейнер из compose): каталог проекта, тома
    проекта и, по галочке, образы; восстановление — `compose up`.

## v1.10.97 — 2026-09-25

- **Запуск контейнера — в окне выполнения nkt, с причиной.** Раньше при
  отказе показывалось «HTTP 500» без объяснения (Docker API отвечает
  кодом, а причину кладёт в тело ответа). Теперь причина — в сообщении
  («port is already allocated», «no such image»…), а start/restart идут
  в стандартном окне: вывод `docker start`, через несколько секунд —

- **Логи контейнера** — иконка в строке (Docker и Podman): `docker logs`
  живьём в окне, хвост 200/1000/5000 строк, «следить», «метки времени».
- **Docker compose блоками: не только сервисы.** Разделы `networks`,
  `volumes`, `secrets`, `configs` — элементами: изменить, удалить,
  `+ network`/`+ volume`/`+ secret`/`+ config` с шаблоном; если раздела
  ещё нет, он создаётся вместе с первым элементом.
- **Дифф перед записью блока** для всех сервисов (nginx, haproxy,
  caddy, compose, libvirt): «Сохранить» показывает «на диске → после
  правки», «Записать» применяет — как в редакторе XML машины.

## v1.10.90 — 2026-09-24

- **Ключ хаба — с готовыми командами.** В окне с публичным ключом (при

  последние строки журнала службы и добавляет их к ошибке и к метке
  «недоступен»: видно, стартует ли nkt по кругу, занят ли порт или
  слушатель ещё не поднялся.

## v1.10.89 — 2026-09-24

- **Перезапуск nkt на хосте больше не роняет запросы.** После «обновить
  пакеты» (или самообновления) служба на секунды не слушает, и страницы
  падали с «connection refused». Теперь хаб, если хост недавно отвечал
  по SSH, ждёт до 20 с и повторяет вход; если API так и не поднялся —
  пишет прямо: «SSH отвечает, но API nkt не поднялся — „обновить“ с хаба
  переустановит и перезапустит службу». Та же подсказка — у метки
  «недоступен» в списке хостов.
- **«Обновить всё» не теряет хосты.** Одновременно обновляются не
  больше трёх (остальные ждут — видно в журнале задания): десятки
  SSH-подключений разом упирались в лимиты sshd или jump-хоста, и хосты
  оказывались «недоступны», хотя «открыть» их обновлял. Временная ошибка
  SSH (отказ, обрыв, таймаут) повторяется трижды с паузой. После
  успешного обновления хост опрашивается сразу — метка «недоступен» не
  висит до следующего тика.

## v1.10.83 — 2026-09-24

- **Бета-релизы.** Тег `vX.Y.Z-beta` собирает бету: релиз помечен
  pre-release, бинарник несёт версию `X.Y.Z-beta`, образ хаба — `:X.Y.Z-beta`
  и `:beta` (`:latest` не трогается). В «О системе» — галочка
  **«использовать бета-версии»**: с ней беты считаются за обновления,
  без неё хаб на бете обновится до стабильной той же версии, когда она
  выйдет. Бета-сборка помечена бейджем «beta» в шапке.
- **Разбор ИИ больше не висит до ошибки.** Причина — общий таймаут
  запросов интерфейса в 30 с и предел хаба в 90 с: локальная модель с
  длинным разбором не успевала, а «Проверить» с коротким вопросом —
  успевала. Теперь у ИИ своя настройка **«время ожидания ответа»**
  (10–1800 с), окно разбора показывает счётчик секунд, а по истечении
  срока приходит понятный отказ с подсказкой.
