# Возможности NetKnownsThat

Полный список того, что умеет nkt, — по разделам интерфейса, в порядке
меню. Одна строка — одна возможность. Как это установить и запустить —
в [README.ru.md](README.ru.md), про хаб подробно — в [HUB.md](HUB.md),
что менялось от версии к версии — в [WHATSNEW.md](WHATSNEW.md).
English version: [FEATURES.md](FEATURES.md).

## Общее

- Один статический бинарник: веб-интерфейс, API, терминальный интерфейс и хаб.
- Три режима: `local` (боевой хост), `fixtures` (снимок хоста для разработки, работает и на Windows), `hub`.
- Интерфейс на русском и английском: язык выбирается по браузеру, переключается внизу меню, все сообщения сервера приходят на языке интерфейса.
- Светлая, тёмная и системная тема.
- Учётные записи с ролями `admin` и `viewer`, пароли argon2id, сессии, защита от перебора, вход системной учётной записью хоста (PAM).
- Режим «только чтение» (`NKT_ALLOW_MUTATIONS=false`), в котором любые изменения отключены.
- Журнал действий: каждое изменение записывается с пользователем, результатом и выводом команды.
- Работа под systemd в песочнице (`ProtectSystem=strict`) с контролируемым выходом из неё для команд, которым нужен доступ к системе.
- Кнопка «Разрешить запись» открывает каталог юниту (drop-in `ReadWritePaths`) и перезапускает службу, когда конфиг лежит вне разрешённых путей.
- Диагностика песочницы: почему не работает терминал или выход из неё, с командами для исправления.
- Фоновые задания с журналом, шагами, отменой и продолжением после перезапуска службы; раздел «Задания».
- Планировщик фоновых проверок и сбора метрик (`NKT_SCHEDULER_ENABLED`).
- Самообновление хоста через хаб или вручную загруженным бинарником.
- Собственный TLS для веб-интерфейса (`NKT_TLS_*`) с автоматическим самоподписанным сертификатом.
- JSON API ко всему, что видно в интерфейсе, с той же авторизацией.

## Состояние

### Обзор
- Сводка хоста: ОС, ядро, время работы, нагрузка, память, диски, сеть.
- Что изменилось с прошлого захода: новые и исчезнувшие проблемы, сервисы, контейнеры, сертификаты.
- Счётчики находок по серьёзности с переходом в «Проблемы».
- Кнопка пересканирования хоста.
- Список известных пакетов-помощников (htop, ncdu, jq…) с отметкой «установлен» и установкой в один клик.

### Проблемы
- Анализ конфигов nginx, haproxy, caddy, docker compose, firewall и сертификатов, сверенный с реальным состоянием хоста.
- Каждая находка: серьёзность, объяснение, файл и строка, конкретное действие для исправления, ссылки на документацию.
- Правила по сети и firewall: конфликты портов, объявлено-но-не-слушает, слушает-но-не-объявлено, отсутствие default deny, публичный порт за firewall, обход firewall контейнерами Docker, устаревшие правила, чувствительные сервисы на всех интерфейсах.
- Правила по TLS: слабые протоколы, отсутствие HSTS, сертификат не указан, просрочен, истекает, ещё не действителен, не читается, не покрывает имя, не продлевается автоматически, осиротевшая линейка certbot, самоподписанный, слабый ключ или подпись, сервис не перечитал сертификат, публичный HTTP-прокси без шифрования.
- Правила по пулам и контейнерам: несуществующий или неиспользуемый upstream, бэкенд не слушает, все бэкенды выключены, единственный бэкенд, нет health-check, контейнер в цикле перезапуска, не запущен, не объявлен, без политики перезапуска, панель статистики haproxy без пароля.
- Расхождение хоста с применённым профилем — как находка.
- Поиск и фильтр по серьёзности, сервису и тексту.

### Уязвимости
- Сканирование установленных пакетов ОС на CVE через trivy (база скачивается автоматически или берётся с хаба).
- Сканирование образов контейнеров Docker/Podman на хосте.
- Установка trivy автоматически при первом скане.
- Список уязвимостей с серьёзностью, пакетом, исправленной версией и ссылками; фильтры.
- Ход сканирования в реальном времени.

### Карта ресурсов
- Граф «внешняя сеть → сервис → слушатель → пул → бэкенд → контейнер → docker-сеть», построенный из конфигов и реального состояния.
- Состояние узлов по живым слушателям, контейнерам и находкам.
- Стабильная раскладка по колонкам, масштабирование и перетаскивание мышью, подробности узла по наведению.

## Наблюдение

### Доступность
- Проверка каждого объявленного слушателя и бэкенда по расписанию: TCP-соединение или HTTP-запрос с верным заголовком Host.
- Тепловая карта «час недели × простой», графики доступности и задержки, список сбоев.
- Свои цели проверки помимо найденных автоматически.

### Нагрузка
- Графики нагрузки по счётчикам iptables, `docker stats` и логам доступа nginx/haproxy за выбранный период, рейтинг самых нагруженных ресурсов, расписание нагрузки по часам.
- Живой `btop` в окне терминала с установкой, если его нет, и подсказками по клавишам.

### Логи
- Логи journald по юнитам и файлы из `/var/log`, включая архивные и сжатые.
- Живое слежение за логом через WebSocket с фильтром, подсветкой, учётом регистра и автопрокруткой.
- Открепление окна лога в отдельное окно браузера.

### Задания
- Список фоновых заданий хоста: вид, шаг, статус, автор, длительность.
- Журнал задания в реальном времени, отмена; прерванные перезапуском задания продолжаются или помечаются.

### Журнал действий
- Все изменения через интерфейс и API: кто, что, когда, с каким результатом и выводом команды; фильтры по действию и результату.
- Состояние фоновых задач планировщика: интервал, последний запуск, обработано, ошибки.

## Хост

### Сервисы
- Список юнитов systemd с состоянием, автозапуском, описанием и портами.
- Действия: запустить, остановить, перезапустить, перечитать, включить/выключить автозапуск, журнал юнита.
- Проверка конфигурации сервиса (`nginx -t`, `haproxy -c`, …) перед действием.
- «Другие сервисы»: процессы, запущенные вручную или из контейнера, с сокетами и открытостью наружу; завершение по SIGTERM/SIGKILL.
- Установка отсутствующего сервиса пакетом с живым журналом apt.
- Проверка открытого порта: TCP, HTTP/HTTPS, TLS-рукопожатие, произвольный `curl` — с телом, заголовками, отрисовкой полученной страницы и скачиванием ответа.

### Контейнеры и ВМ
- **Docker**: контейнеры (статус, образ, порты, сети), запуск/остановка/перезапуск/удаление, логи, создание контейнера, сканирование compose-стеков.
- **Docker → образы**: список с размером, датой и использованием, удаление, сохранение в tar на хосте, очистка осиротевших слоёв.
- **Docker → стеки**: compose-файлы хоста, `up`/`down`/`restart`, редактирование compose через редактор конфигов, новый стек из шаблона.
- Установка Docker с официального репозитория docker.com (или скриптом get.docker.com) с живым журналом.
- **Podman**: контейнеры через собственный сокет, тот же жизненный цикл.
- **LXD**: контейнеры и виртуальные машины, `launch`, запуск/остановка, удаление.
- **Виртуальные машины (libvirt/QEMU)**: список доменов, запуск/выключение/принудительное выключение/перезагрузка, автозапуск, удаление с дисками или без, адреса машин.
- Создание машины из облачного образа: имя, ядра, память, диск, сеть, пользователь и SSH-ключ через cloud-init; недостающие программы ставятся сами; шаблоны машин для повторного создания.
- Каталог облачных образов (Ubuntu, Debian, …) и свои образы: скачивание с проверкой контрольной суммы, загрузка своего файла, перенос в каталог дисков.
- Сети libvirt: список, создание NAT-сети с DHCP и автозапуском, проверка подсети на пересечение с сетями и интерфейсами хоста, мост на интерфейс хоста.
- Редактирование XML домена через редактор конфигов с проверкой `virt-xml-validate` и применением `virsh define`.
- **Профили**: описание желаемого состояния хоста в YAML — пакеты, службы, файлы, правила firewall, учётные записи, системные настройки, compose-стеки.
- План применения профиля с отметкой опасных пунктов, применение заданием с журналом, проверка расхождений по расписанию.
- Экспорт и импорт профилей, версии профиля, справочник по формату на двух языках прямо в интерфейсе.

### Пакеты
- Поиск пакетов apt с ранжированием по совпадению, установка нескольких пакетов одной транзакцией.
- Список установленных пакетов сеткой с поиском и удалением.
- Доступные обновления и `apt-get upgrade` в живом окне терминала (без `-y`, с подтверждением).
- Пакеты snap и flatpak: список, обновление, удаление.
- Описание пакета по наведению.

### Конфигурации
- Все найденные конфиги nginx, haproxy, caddy, docker compose, systemd, cron, sshd, netplan, libvirt — по категориям, с переходом к строке из находки.
- Редактор с номерами строк; перед записью конфиг проверяется самим сервисом, при провале файл возвращается к прежнему виду автоматически.
- История версий каждого файла: просмотр, сравнение (diff), откат к любой версии, заметка к изменению.
- Применение после записи: `reload`/`restart` сервиса, `docker compose up`, `virsh define`, `netplan` — с проверкой.
- Блочный редактор: дерево блоков nginx/haproxy (`server`, `location`, `frontend`, `backend`), добавление, правка и удаление блока без риска сломать соседние.
- Защита sshd: перед записью проверяется, останется ли путь на хост, если sshd не поднимется; после записи — что sshd принимает соединения, иначе откат.
- Новый файл в каталоге категории с обходом только вглубь корня.
- Запись в каталоги вне песочницы с предложением «Разрешить запись».

### Диски
- Файловые системы с занятостью, псевдо-ФС скрыты по умолчанию.
- «Что занимает место»: размеры подкаталогов по клику, уровень за уровнем.
- Подкачка, физические диски и разделы с раскрытием.
- **Файлы**: проводник по разрешённым корням (`/home`, `/srv`, `/opt`, `/var/www`, `/tmp`; настраивается) — папки, переименование, удаление, скачивание.
- Загрузка файлов и целых папок через диалог или перетаскиванием, с общим прогрессом; дерево папок повторяется на хосте.
- Распаковка zip/tar-архивов на месте с защитой от путей наружу.
- `git clone` заданием с журналом, в том числе приватных репозиториев: токен по HTTPS или deploy-ключ хоста по SSH.
- Редактор файла с номерами строк, переименованием, сохранением прав и защитой от затирания чужой правки.

### Оборудование
- Машина, процессор, память, батареи, температуры (lm-sensors), PCI- и USB-устройства.

### Системные настройки
- Имя машины, часовой пояс (с поиском), флаг NTP, состояние автоматических обновлений безопасности.
- Локали: все известные системе ячейками с поиском, генерация выбранных, назначение основной.
- Синхронизация времени: какая служба стоит (systemd-timesyncd, chrony, ntpsec), с кем сверяется, stratum и расхождение; выбор серверов NTP из списка или своих; «синхронизировать сейчас»; установка службы, если её нет.
- NetworkManager: соединения, устройства, Wi-Fi-сети, подключение с паролем.

### Терминал
- Полноценная интерактивная оболочка на хосте в браузере (`NKT_TERMINAL_ENABLED`), tmux-сессии, открепление в отдельное окно.
- Панель инструментов: копирование, очистка, размер шрифта, поиск.
- Установка tmux и dbus-помощников, если их нет.

## Сеть

### Сетевые интерфейсы
- Интерфейсы с адресами, состоянием, счётчиками и ошибками; вид интерфейса (мост, veth, WireGuard, туннель, libvirt) и подключённые к нему контейнеры.
- Слушающие сокеты с процессами; у открытых на `0.0.0.0` портов — проверка порта в один клик.

### Firewall
- **ufw**: состояние, правила с номерами, добавление и удаление правил (порт/протокол/источник/комментарий), включение с защитой порта 22.
- **firewalld**: зоны, службы, порты, добавление и удаление на время и постоянно, `reload`.
- Установка ufw или firewalld пакетом с живым журналом, если на хосте ничего нет.
- Просмотр iptables как есть (без редактирования).

### Сертификаты
- Все сертификаты из конфигов nginx, haproxy, caddy и `/etc/letsencrypt`: срок, имена, издатель, алгоритм, ключ, самоподписанность.
- Каталоги `crt` у haproxy раскрываются по SNI, производные копии находятся по отпечаткам.
- Сверка с реальным TLS-сокетом: сервис отдаёт тот же сертификат, что лежит на диске.
- Состояние автопродления: знает ли certbot, активен ли таймер или cron.
- Продление линейки certbot через `--standalone` с остановкой и возвратом занимающих 80/443 служб и процессов (в том числе запущенных вручную), с их перезапуском.
- Выпуск нового сертификата Let's Encrypt; проверка и установка certbot, если его нет.
- Сборка PEM для haproxy из линейки certbot с перезагрузкой haproxy.
- Самоподписанный сертификат: RSA 2048/3072/4096, несколько имён, wildcard, юникод-домены.
- Заготовки конфигов nginx, haproxy и caddy под выпущенный сертификат с копированием в буфер.
- Автопродление по расписанию (`NKT_AUTO_RENEW_CERTS`).

## Доступ

### Пользователи
- Учётные записи nkt: создание, роль, отключение, смена пароля, сброс сессий.

### Учётные записи хоста
- Системные пользователи с оболочкой, домом, группами и sudo.
- Создание пользователя с SSH-ключом, выдача sudo без пароля, удаление.

## Хаб

- Один хаб управляет многими хостами: хост подключается по SSH (пароль или ключ), nkt ставится на него автоматически с нужной архитектурой.
- Хосты собраны в группы; у каждого — статус, версия nkt, проблемы, доступность, sudo и резервный канал.
- Открытие любого хоста в том же интерфейсе — все разделы выше работают через хаб.
- Строка «localhost» — сама машина хаба без SSH.
- Установка, обновление, переустановка, остановка и запуск nkt на хосте; «обновить всё» для отставших.
- Хост с версией, отличной от хаба (старее или новее), приводится к версии хаба при открытии.
- Резервный канал (обратный TLS-туннель с привязкой сертификата) на случай, когда SSH недоступен.
- Отзыв sudo NOPASSWD, диагностика адреса, полное удаление nkt с хоста (с восстановлением входа по паролю).
- Машины внутри хоста: создание виртуальной машины на хосте из хаба, автоматическая установка nkt в неё, применение профиля; поиск уже существующих машин и добавление их в список; запуск/выключение через хост-родитель; удаление вместе с дисками.
- Профили по группам хостов: применение одного профиля ко всей группе заданием.
- Оповещения: недоступен, снова отвечает, появились серьёзные проблемы, исправлены, задание упало; журнал оповещений с настройками, что записывать и о чём уведомлять, сворачивание коротких эпизодов; уведомления браузера.
- Задания хаба с журналом.
- Экспорт и импорт хаба целиком: хосты с секретами, группы, машины с родителями, профили с историей, шаблоны машин, настройки; файл шифруется паролем.
- Централизованная база уязвимостей trivy для всех хостов, обновление по расписанию и по кнопке.
- «О системе»: версия хаба, проверка релизов GitHub, обновление до последней, откат на предыдущую, описание новой версии до установки.
- Настройка через `hub.env`, запуск как systemd-юнит, в Docker Compose или Kubernetes.

## Терминальный интерфейс (`nkt tui`)

- Те же данные в терминале: обзор, проблемы, карта ресурсов деревом, сервисы, контейнеры, сертификаты, конфигурации, доступность и нагрузка.
- Управление сервисами и контейнерами, продление сертификатов, откат конфигов.
- На русском и английском.

## Командная строка

- `nkt serve` — запуск веб-интерфейса; `nkt scan` — разовый скан в JSON; `nkt version`.
- `nkt users` и `nkt passwd` — учётные записи и пароли без веб-интерфейса.
- `nkt hub` — запуск хаба; `nkt hub import` — восстановление реестра; `nkt hub delete` — полное удаление данных хаба с предложением экспорта.
