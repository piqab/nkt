# Пользователи, учётные записи хоста, безопасность

## Пользователи nkt

![Пользователи](/screens/ru/users.png)

Учётные записи самого nkt: роли `admin` и `viewer` (только чтение),
создание, отключение, смена пароля, сброс сессий. Свою учётку понизить
или удалить нельзя — чтобы не потерять доступ случайно. Вход возможен и
системной учётной записью хоста (PAM).

Из командной строки:

```bash
sudo nkt passwd                      # сменить пароль администратора
sudo nkt passwd ops -role viewer     # учётка только для чтения
sudo nkt passwd -random              # сгенерировать пароль
sudo nkt users                       # кто есть и кто когда входил
```

`nkt passwd` пишет прямо в базу — этим же лечится «забыл пароль».

## Учётные записи хоста

Системные пользователи с оболочкой, домом, группами и sudo. Создание
пользователя с SSH-ключом, выдача sudo без пароля, удаление.

## Безопасность

- Пароли — argon2id; сессии — случайные отзываемые токены; cookie
  `HttpOnly`, `SameSite=Lax`; защита от перебора.
- Слушает только `127.0.0.1`; `NKT_COOKIE_SECURE=true` по умолчанию —
  без HTTPS браузер не примет cookie.
- `NKT_ALLOW_MUTATIONS=false` — режим только чтения для всего
  приложения.
- Работает под systemd в песочнице (`ProtectSystem=strict`), с
  контролируемым выходом из неё только для команд, которым нужен доступ
  к системе; диагностика песочницы — в интерфейсе.
- Каждое изменение — в [журнале действий](/guide/monitoring#журнал-действий).

::: danger
Доступ к nkt равносилен root на хосте. Не открывайте его в интернет без
отдельного слоя аутентификации.
:::
