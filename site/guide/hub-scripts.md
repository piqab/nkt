# Сценарии

::: warning Экспериментальная возможность
Сценарий делает на хостах ровно то, что написано, и без отката. Сначала
«Проверить» и «Сухой прогон», обкатывайте на тестовых машинах,
проверяйте журнал задания.
:::

![Сценарии](/screens/ru/hub-scripts.png)

Сценарий — список действий на языке из нескольких команд: завести
группу и хосты, поставить nkt, пакеты, Docker, стеки, машины. Хаб
выполняет его по порядку теми же вызовами, что и кнопки интерфейса, и
останавливается на первой ошибке. Одна строка — одно действие;
compose-файл или текст файла кладётся блоком до `end`.

Где: **«Профили» → вкладка «Сценарии»**. «Новый сценарий» открывает окно
редактора; в нём **«Готовые сценарии ▾»** вставляет пример целиком. Дальше —
имя, «Сохранить», «Проверить», «Сухой прогон», «Выполнить».

```
param ADDR "адрес нового сервера"
group prod profile web-base
host web1 ${ADDR} user root password ask group prod
install web1
wait web1 online 5m
on web1 packages install nginx htop
on web1 service nginx enable
on web1 firewall allow 80/tcp
on web1 firewall allow 443/tcp
wait web1 http http://${ADDR}/ 200 1m
```

## Команды

| Команда | Что делает |
|---|---|
| `set ИМЯ значение`, `set ИМЯ ask` | переменная; `ask` — спросить при запуске, не хранить |
| `param ИМЯ "подсказка"` | параметр, который спрашивают при запуске — один сценарий для разных стендов |
| `group ИМЯ [profile ПРОФИЛЬ]` | группа на хабе |
| `host ИМЯ АДРЕС[:ПОРТ] user … (password ask \| password "…" \| key hub) [group …]` | завести хост |
| `install ХОСТ…` | поставить nkt |
| `wait ХОСТ online \| port N \| http URL [КОД] \| service ИМЯ active` | подождать |
| `wait url URL [КОД] [ДЛИТЕЛЬНОСТЬ]` | подождать ответа адреса снаружи: запрос с хаба по настоящему имени — DNS, шлюз и сертификат проверяются, как у пользователя |
| `on ХОСТ… packages install\|remove …` | пакеты; в `on` можно перечислить несколько хостов |
| `on ХОСТ service ИМЯ start\|stop\|restart\|reload\|enable\|disable` | службы |
| `on ХОСТ firewall allow\|deny ПОРТ [from CIDR]` | firewall |
| `on ХОСТ docker install`, `on ХОСТ docker stack ПУТЬ up\|down … end` | Docker и compose-стек |
| `on ХОСТ vm create ИМЯ image ОБРАЗ [cpu N] [mem МБ] [disk ГБ] [profile …] [install]` | машина на хосте |
| `on ХОСТ apply profile ПРОФИЛЬ` | применить профиль |
| `on ХОСТ file put ПУТЬ … end` | записать файл |
| `on ХОСТ user add ИМЯ [sudo] [key "…"]` | учётная запись |
| `on ХОСТ system hostname\|timezone\|locale\|ntp …` | системные настройки |
| `on ХОСТ cert issue ДОМЕН… \| cert renew ДОМЕН` | сертификат Let's Encrypt |
| `on ХОСТ git clone URL /КАТАЛОГ [branch …] [token ask]` | клонировать репозиторий |
| `on ХОСТ k8s create ИМЯ [nodes single\|1+N\|3+N\|"ХОСТ: cp N, w N, host cp\|w; …"] [network nat\|bridge\|wireguard] [cni cilium] [expose] …`, `on ХОСТ k8s destroy ИМЯ` | кластер Kubernetes на машинах хоста или с размещением по нескольким хостам (экспериментально) |
| `pipeline ИМЯ` … `end` | сохранить конвейер выкладки — описание блоком, как «Сохранить» в окне конвейера: значения `env:` — в секреты, `generate:` создаёт хаб, другое значение уже заданного ключа — ошибка |
| `deploy КОНВЕЙЕР [ДЛИТЕЛЬНОСТЬ]` | выложить конвейер и дождаться итога; в сухом прогоне — сухой прогон конвейера |
| `k8s КЛАСТЕР ingress cilium [port N]` | включить Ingress Cilium в режиме host network (порт на каждом узле, по умолчанию 8080); нужен кластер с Cilium и заменой kube-proxy |
| `k8s КЛАСТЕР apply` … `end` | применить манифест на первом control plane, как «Манифесты» раздела «Кластеры»; в сухом прогоне — `kubectl diff` |
| `k8s КЛАСТЕР wait deployment ИМЯ [namespace NS] [ДЛИТЕЛЬНОСТЬ]` | дождаться готовности всех реплик |
| `fly route ИД ВИД [names …] [port N] [tls gateway] [check …] [gateway ШЛЮЗ] (targets cluster КЛАСТЕР port N \| target ХОСТ ВИД ИМЯ ПОРТ …)` | создать или обновить маршрут Traffic Fly и применить, как блок `fly:` конвейера; `targets cluster` — все узлы кластера |
| `fly apply` | применить карту Traffic Fly |
| `migrate ХОСТ КОНТЕЙНЕР to ХОСТ [switch-fly] [switch-pipeline] [clean-leftovers]` | перенести стек на другой хост, как с карты хостов: план с препятствиями, перенос, откат при ошибке; в сухом прогоне — план |

Полная справка с примерами, которые можно скопировать или вставить в
редактор, — вкладка «Справка» на странице сценариев (справа, рядом с
«Текст» и «Схема»); те же готовые сценарии — «Готовые сценарии ▾» в окне
редактора.

## ИИ в редакторе

Если в «О системе» включён разбор моделью, в окне редактора есть кнопка
**«ИИ ▾»**:

- **«Объяснить выделенное»** (без выделения — весь текст): что делает каждый
  шаг на хостах, что изменится и чем рискованно;
- **«Написать по строкам „# ИИ: …“»**: строка `# ИИ: поставить nginx на web1
  и открыть 443` — задание; модель пишет команды под ней, остальное не
  трогает;
- **«Сценарий по описанию задачи»**: поле «что сделать» → сценарий целиком.

Модель видит справку языка (ту же, что вкладка «Справка») и **имена**
хостов, групп, профилей, конвейеров, кластеров и шлюзов — адреса, пароли и
секреты не уходят; с «маскировкой» в настройках ИИ имена хостов уходят
псевдонимами. Ответ сразу проходит «Проверить»; ошибки уходят модели на
одну повторную попытку, оставшиеся показываются по строкам. Новый текст
попадает в редактор только через окно с диффом («Вставить в редактор»);
**ИИ сценарий не запускает** — дальше обычные «Сохранить», «Сухой прогон»,
«Выполнить».

## По API и из n8n

Сохранённый сценарий запускается и без интерфейса — API-токеном
администратора (`POST /api/hub/scripts/{id}/run` с ответами на вопросы и
`dry_run`) или узлом n8n **Script → Run**. Создавать и править сценарии по
токену нельзя — только здесь, с историей версий. Токен с пределом по хостам
запускает только сценарий целиком на его хостах. Подробно —
[API хаба](/guide/hub-api#что-доступно-токену), [n8n](/guide/n8n).

## Проверка, сухой прогон, выполнение

- **Проверить** разбирает текст и сверяет имена хостов, групп и профилей,
  ничего не меняя.
- **Сухой прогон** проходит сценарий: у хостов спрашиваются планы (что бы
  изменилось), остальные шаги пишутся в журнал как «сделал бы»; хосты и
  машины не создаются.
- **Выполнить** сохраняет, проверяет, спрашивает пароли, параметры и
  токены (в текст они не попадают) и запускает задание хаба. После
  перезапуска хаба задание продолжается с той же строки, уже заведённые
  хосты не заводятся второй раз.

## Схема

![Схема сценария](/screens/ru/hub-script-scheme.png)

Вкладка «Схема» рисует сценарий: группы → хосты → действия, машины
внутри хоста, на котором создаются. Редактируется текст; схема нужна,
чтобы окинуть сценарий взглядом.
