# Сценарии

::: warning Экспериментальная возможность
Сценарий делает на хостах ровно то, что написано, и без отката. Сначала
«Проверить» и «Сухой прогон», обкатывайте на тестовых машинах,
проверяйте журнал задания.
:::

![Сценарии](/screens/ru/hub-scripts.png)

Сценарий — список действий на языке из нескольких команд: завести
группу и хосты, поставить nkt, пакеты, Docker, стеки, машины. Хаб
выполняет его по порядку теми же вызовами, что и кнопки интерфейса, и
останавливается на первой ошибке. Одна строка — одно действие;
compose-файл или текст файла кладётся блоком до `end`.

Где: **«Профили» → вкладка «Сценарии»**. «Новый сценарий» открывает окно
редактора; в нём **«Готовые сценарии ▾»** вставляет пример целиком. Дальше —
имя, «Сохранить», «Проверить», «Сухой прогон», «Выполнить».

```
param ADDR "адрес нового сервера"
group prod profile web-base
host web1 ${ADDR} user root password ask group prod
install web1
wait web1 online 5m
on web1 packages install nginx htop
on web1 service nginx enable
on web1 firewall allow 80/tcp
on web1 firewall allow 443/tcp
wait web1 http http://${ADDR}/ 200 1m
```

## Команды

Все команды с синтаксисом, аргументами и примерами, а также готовые
сценарии — на странице **[Команды сценариев](/guide/script-commands)**. Она
собирается из того же описания команд в коде nkt, по которому работают
«Проверить», вкладка «Справка» и ИИ, поэтому всегда совпадает с тем, что
понимает хаб. Коротко:

- переменные и вопросы при запуске: `set`, `param`;
- хаб: `group`, `host`, `install`, `wait`, `wait url`;
- на хосте (`on ХОСТ… …`): пакеты, службы, firewall, Docker и
  compose-стеки, машины, профили, файлы, учётные записи, системные
  настройки, сертификаты, `git clone`, кластеры Kubernetes;
- выкладки и переносы: `pipeline`, `deploy`, `migrate`;
- кластеры и Traffic Fly: `k8s … ingress|apply|wait`, `fly route`, `fly apply`.

![Вкладка «Справка»: страница «Команды сценариев» с сайта](/screens/ru/hub-script-help.png)

Справка по командам — и в редакторе: значок «?» в заголовке окна и
вкладка «Справка» на странице сценариев (та же страница сайта; без
доступа к сайту — справка из nkt), готовые сценарии — «Готовые сценарии
▾» в окне редактора.

## ИИ в редакторе

Если в «О системе» включён разбор моделью, в окне редактора есть кнопка
**«ИИ ▾»**:

- **«Объяснить выделенное»** (без выделения — весь текст): что делает каждый
  шаг на хостах, что изменится и чем рискованно;
- **«Написать по строкам „# ИИ: …“»**: строка `# ИИ: поставить nginx на web1
  и открыть 443` — задание; модель пишет команды под ней, остальное не
  трогает;
- **«Сценарий по описанию задачи»**: поле «что сделать» → сценарий целиком.

Модель видит справку языка (ту же, что вкладка «Справка») и **имена**
хостов, групп, профилей, конвейеров, кластеров и шлюзов — адреса, пароли и
секреты не уходят; с «маскировкой» в настройках ИИ имена хостов уходят
псевдонимами. Ответ сразу проходит «Проверить»; ошибки уходят модели на
одну повторную попытку, оставшиеся показываются по строкам. Новый текст
попадает в редактор только через окно с диффом («Вставить в редактор»);
**ИИ сценарий не запускает** — дальше обычные «Сохранить», «Сухой прогон»,
«Выполнить».

Пример. В редакторе одна строка-задание:

```
# ИИ: поставить nginx на web1 и открыть 443
```

«ИИ ▾» → «Написать по строкам „# ИИ: …“» — в окне диффа под строкой
появляются команды, строка-задание остаётся комментарием:

```
# ИИ: поставить nginx на web1 и открыть 443
on web1 packages install nginx
on web1 service nginx enable
on web1 firewall allow 443/tcp
wait web1 port 443 1m
```

Под диффом — итог «Проверить» (здесь — без ошибок); «Вставить в
редактор» — и дальше как с обычным текстом. «Сценарий по описанию
задачи» делает то же для всего сценария: «nginx на web1 и web2, порты 80 и
443, дождаться 80 на web1» → сценарий целиком.

## По API и из n8n

Сохранённый сценарий запускается и без интерфейса — API-токеном
администратора (`POST /api/hub/scripts/{id}/run` с ответами на вопросы и
`dry_run`) или узлом n8n **Script → Run**. Создавать и править сценарии по
токену нельзя — только здесь, с историей версий. Токен с пределом по хостам
запускает только сценарий целиком на его хостах. Подробно —
[API хаба](/guide/hub-api#что-доступно-токену), [n8n](/guide/n8n).

## Проверка, сухой прогон, выполнение

![Черновик ассистента в редакторе: имя, заметка и проверка — сами](/screens/ru/hub-script-editor.png)

- **Проверить** разбирает текст и сверяет имена хостов, групп и профилей,
  ничего не меняя. Кнопка есть и в окне редактора: итог — под текстом,
  ошибки по строкам. Ловит и блок, закрытый не там: если в YAML блока
  оказались команды сценария (`on …`, `wait …`), — «`end` не на месте».
- **Сохранить** в окне редактора доступна, когда у сценария есть имя и
  текущий текст прошёл «Проверить»; любая правка снова требует проверки.
  Рядом с неактивной кнопкой написано, чего не хватает.
- **Черновик из ИИ** («Открыть как сценарий» в ответе ассистента или
  разборе находки) открывается с именем латиницей
  (`ai-20261023-1532-web-1` или `fix-web-1-20261023-1532`), заметкой
  «Предложено ассистентом: …» или «Из разбора находки: …» и уже
  проверенным — «Сохранить» сразу доступна. В списке у таких сценариев
  метка «ИИ». Скачанный сценарий называется латиницей.
- **Сухой прогон** проходит сценарий: у хостов спрашиваются планы (что бы
  изменилось), остальные шаги пишутся в журнал как «сделал бы»; хосты и
  машины не создаются.
- **Выполнить** сохраняет, проверяет, спрашивает пароли, параметры и
  токены (в текст они не попадают) и запускает задание хаба. После
  перезапуска хаба задание продолжается с той же строки, уже заведённые
  хосты не заводятся второй раз.

## История версий

![История версий сценария: разница с предыдущей](/screens/ru/hub-script-history.png)

Каждое сохранение — новая редакция. «История» (на карточке сценария и в
окне редактора) — таблица: №, время, автор, заметка к правке, размер,
метка «текущая». У каждой редакции:

- **«Содержимое»** — текст редакции целиком, только чтение;
- **«Разница»** — дифф с текущей или с предыдущей редакцией
  (переключатель над диффом);
- **«Вернуть в редактор»** — текст редакции попадает в окно правки; на
  хабе ничего не меняется, пока вы не нажмёте «Проверить» и «Сохранить»
  (с диффом перед записью) — так откат тоже остаётся новой редакцией.

Так же устроена история профилей и описаний сервисов.

## Схема

![Схема сценария](/screens/ru/hub-script-scheme.png)

Вкладка «Схема» рисует сценарий: группы → хосты → действия, машины
внутри хоста, на котором создаются. Редактируется текст; схема нужна,
чтобы окинуть сценарий взглядом.
