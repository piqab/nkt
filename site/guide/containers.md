# Контейнеры и виртуальные машины

Один раздел с вкладками: Docker, Podman, LXD и виртуальные машины
libvirt/QEMU.

## Docker

![Контейнеры Docker](/screens/ru/containers.png)

- **Контейнеры**: статус, образ, порты, сети; запуск, остановка,
  перезапуск, удаление, логи; создание контейнера; сканирование
  compose-стеков.
- **Образы**: размер, дата, кем используется; удаление, сохранение в tar
  на хосте, очистка осиротевших слоёв.
- **Стеки**: compose-файлы хоста — `up`, `down`, `restart`; compose
  редактируется в [редакторе конфигов](/guide/configs) с проверкой
  `docker compose config`; новый стек — из шаблона.
- Если Docker на хосте нет — ставится кнопкой с официального репозитория
  docker.com (или скриптом get.docker.com) с живым журналом.

## Podman и LXD

Podman — контейнеры через собственный сокет, тот же жизненный цикл, что у
Docker. LXD — контейнеры и виртуальные машины одним инструментом:
`launch`, запуск, остановка, удаление.

## Виртуальные машины

![Виртуальные машины](/screens/ru/vms.png)

- Домены libvirt: запуск, выключение, принудительное выключение,
  перезагрузка, автозапуск, удаление с дисками или без; адреса машин.
- **Новая машина** из облачного образа: имя, ядра, память, диск, сеть,
  пользователь и SSH-ключ через cloud-init. Недостающие программы
  (`virt-install`, `qemu-img`…) ставятся сами. Шаблоны машин — чтобы
  создавать одинаковые повторно.
- **Образы**: каталог облачных образов Ubuntu, Debian и др. — скачивание с
  проверкой контрольной суммы; свои образы — загрузка файла, перенос в
  каталог дисков.
- **Сети libvirt**: список, NAT-сеть с DHCP и автозапуском (подсеть
  проверяется на пересечение с сетями и интерфейсами хоста), мост на
  интерфейс хоста.
- XML домена редактируется в редакторе конфигов с проверкой
  `virt-xml-validate` и применением через `virsh define`.

::: tip Машины из хаба
На хабе машина создаётся на хосте прямо из списка хостов, nkt ставится в
неё автоматически, а профиль группы применяется сразу — см.
[Хаб](/guide/hub).
:::
