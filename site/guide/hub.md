# Хаб: много хостов из одного места

Обычный `nkt` управляет одним хостом. `nkt hub` — тот же бинарник в другом
режиме: он стоит на отдельной машине и управляет остальными **по SSH**,
показывая для каждого ту же панель, что показал бы обычный nkt — с выбором
хоста в интерфейсе вместо отдельной установки на каждый.

![Хосты на хабе](/screens/ru/hub-hosts.png)

## 1. Установка

Тот же бинарник, что и для хоста ([как его получить](/guide/getting-started#_1-бинарник)),
другой юнит и env-файл:

```bash
sudo install -d -m 0750 /etc/netknownsthat
curl -fsSL https://raw.githubusercontent.com/piqab/nkt/main/deploy/hub.env.example \
  | sudo install -m 0640 /dev/stdin /etc/netknownsthat/hub.env
curl -fsSL https://raw.githubusercontent.com/piqab/nkt/main/deploy/netknownsthat-hub.service \
  | sudo install -m 0644 /dev/stdin /etc/systemd/system/netknownsthat-hub.service
sudo $EDITOR /etc/netknownsthat/hub.env
sudo systemctl daemon-reload
sudo systemctl enable --now netknownsthat-hub
```

Из клона репозитория то же делает `sudo make hub-install`. Есть и готовый
образ для Docker Compose и Kubernetes — манифесты в
[`deploy/`](https://github.com/piqab/nkt/tree/main/deploy), подробности в
[HUB.md](https://github.com/piqab/nkt/blob/main/HUB.md).

Проверить, что поднялось:

```bash
curl -s http://127.0.0.1:8077/api/health
journalctl -u netknownsthat-hub -f
```

Хаб, как и nkt, слушает только `127.0.0.1` — снаружи нужен SSH-туннель,
`NKT_TLS_ENABLED=true` или обратный прокси с TLS (см.
[установку на хост](/guide/getting-started#_4-открыть-в-браузере)).

## 2. Первый вход

При первом старте хаб создаёт администратора и печатает пароль в журнал:

```
=== Создана учётная запись администратора хаба ===
  логин:  admin
  пароль: <строка>
```

Больше он нигде не показывается — сохраните. Первой строкой в списке хостов
всегда стоит **localhost** — сама машина хаба, без SSH и установки: её
можно открыть сразу.

## 3. Добавить хост

«Добавить хост» → имя, адрес, SSH-порт и пользователь (`root` или
пользователь с `sudo` без пароля — так настроены типовые образы VPS).
Способ входа:

- **хаб сгенерирует ключ** (рекомендуется) — после сохранения хаб покажет
  публичный ключ; добавьте его в `~/.ssh/authorized_keys` на хосте и только
  потом нажимайте «установить». Приватная половина никуда не передаётся.
- **свой приватный ключ** — содержимое `id_ed25519`/`id_rsa` (не `.pub`).
- **пароль** — обычный пароль по SSH. Для свежего сервера, где есть только
  root и пароль, включите **«Подготовить новый хост»**: хаб поставит
  пакеты-помощники, заведёт пользователя с `NOPASSWD`, переведёт вход на
  ключ и по желанию выключит вход по паролю — каждый шаг с проверкой и
  откатом.

Дальше «установить»: хаб копирует бинарник нужной архитектуры, кладёт
юнит и запускает службу; ход виден в живом журнале. Хост появляется в
списке с версией, проблемами и доступностью — «открыть» ведёт в ту же
панель, что и у одиночного nkt.

Полезные переключатели в форме хоста:

- **веб-терминал** — root-shell в браузере, выключен по умолчанию;
- **резервный канал** — обратный TLS-туннель на случай, когда SSH закрыли
  файрволом: панель, терминал и обновления продолжают работать через него.

## 4. Что есть на хабе

- **Группы** — хосты собираются в группы перетаскиванием; у группы может
  быть профиль: машины, создаваемые в ней, делаются по нему.
- **Машины внутри хоста** — виртуальная машина создаётся на хосте прямо из
  хаба, nkt ставится в неё автоматически, применяется профиль.
- **Профили** — желаемое состояние хоста в YAML (пакеты, службы, файлы,
  firewall, учётные записи, compose-стеки) с планом и применением
  заданием; расхождения — как находки.
- **Сценарии** (экспериментально) — построчный язык развёртывания: завести
  группу и хосты, поставить nkt, пакеты, Docker, стеки, машины; сухой
  прогон, справка и схема прямо в интерфейсе.
- **Оповещения** — хост недоступен / снова отвечает / серьёзные проблемы /
  задание упало; настройка, что записывать и о чём уведомлять браузером.
- **Задания** хаба с журналом; **экспорт и импорт** хаба целиком
  (зашифрованный файл); **обновление** и **откат** хаба и всех хостов из
  «О системе»; централизованная база уязвимостей trivy.

Подробно каждая возможность разобрана в
[HUB.md](https://github.com/piqab/nkt/blob/main/HUB.md); список всего — на
странице [возможностей](/features#хаб).
