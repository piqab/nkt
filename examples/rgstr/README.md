# rgstr — свой реестр образов и плагин хаба

> **WARNING:** пример использует сторонний репозиторий и образы — их безопасность и стабильность работы не гарантируются. Проверьте их сами, прежде чем выкладывать в рабочую среду.

[rgstr](https://github.com/piqab/rgstr) — лёгкий реестр образов OCI/Docker
на Go (MIT): `docker push/pull`, проекты с квотами, роботы, вебхуки,
политики хранения и неизменяемости, сборка мусора, журнал, веб-интерфейс
`/ui`; с 1.8 — вход LDAP/OIDC и бэкапы, с 1.9 — кластер на PostgreSQL и
S3, с 1.10 — проекты-кеши других реестров и скан уязвимостей Trivy. Один
экземпляр хранит данные на диске, без базы. В Kubernetes его ставит оператор
[rgstroperator](https://github.com/piqab/rgstroperator) — подробно в
статье справки «rgstr и rgstroperator в nkt».

## Выкладка конвейером

«Примеры» → «rgstr — реестр образов», хост, имя в `site:`. Стек —
[`deploy/docker-compose.yml`](deploy/docker-compose.yml) (rgstr 1.10.1,
том `rgstr-data`), сайт с HTTPS и `max_body: "0"` (слои образов идут
потоком, без предела размера).

- Вход включён; секрет токенов создаёт хаб (`generate:hex32`).
- Первый администратор — `RGSTR_ADMIN_USER` с **временным** паролем из
  `.env` («Секреты» → «.env» → история → «Показать»). Войдите в
  `https://<домен>/ui` и смените его — до этого им нельзя ни `docker
  login`, ни плагину.
- Удалять может только администратор (`RGSTR_ADMINS`).
- **Скан уязвимостей** включён (`RGSTR_SCAN_ENABLED`, по умолчанию
  `true`): Trivy уже в образе, его база (~70 МБ) качается из интернета
  (`mirror.gcr.io`, запасной — `ghcr.io`) при первом скане. Скан берёт
  несколько сотен МБ памяти; на маленьком хосте или без интернета задайте
  `"false"`.
- **Кеш Docker Hub** — `RGSTR_PROXIES: dockerhub=https://registry-1.docker.io`
  в `env` конвейера; `docker pull <домен>/dockerhub/library/nginx`. Логин и
  токен доступа Docker Hub (`RGSTR_PROXY_DOCKERHUB_USERNAME`, `…_PASSWORD`)
  поднимают лимиты pull; токен — в «Секреты» → «.env».
- **Бэкапы в S3** — `RGSTR_BACKUP_TARGET: s3://бакет/префикс` и
  `RGSTR_BACKUP_S3_*` (endpoint, регион, ключи); расписание по умолчанию —
  `0 3 * * *` UTC, хранится 7.

## Плагин

Ставится на хост rgstr (или на машину хаба, если rgstr оттуда виден):
«Плагины» → «Каталог» → rgstr → «Установить на хост».

| Настройка | Что |
|---|---|
| `RGSTR_URL` | откуда плагин видит rgstr; на хосте rgstr — `http://127.0.0.1:5000` |
| `RGSTR_USER`, `RGSTR_PASSWORD` | администратор rgstr (не временный пароль); пароль — секрет |
| `RGSTR_PUBLIC` | адрес реестра для docker и конвейеров — `registry.example.com` |
| `RGSTR_CA_FILE` | свой УЦ (PEM), если HTTPS rgstr подписан им |

**Что умеет:**

- **Сводка** — версия, вход (и LDAP/OIDC), репозитории, скачивания, диск,
  сборка мусора, скан, бэкапы и находки: вход выключен, реестр по HTTP не
  на 127.0.0.1, временные пароли, мало места, сборка мусора выключена, с
  ошибкой или давно не шла, нет политик хранения, открытые `/metrics`,
  робот с записью во все репозитории, пользователь `user` с правом
  удалять, скан выключен или с ошибкой, критические уязвимости, бэкапы не
  настроены, упали или опоздали, кеш ходит в upstream по HTTP.
- **Репозитории и теги** — худший уровень уязвимостей, удалить тег
  (неизменяемые — нельзя), собрать мусор.
- **Уязвимости** образа — уровень, CVE, пакет, версия и версия с
  исправлением; «Сканировать» ставит образ в очередь.
- **Проекты** — создать (открытый, квота в ГБ, **кеш** другого реестра,
  запрет pull уязвимых образов), сменить запрет pull, удалить пустой.
- **Бэкапы** — куда, расписание, последний удачный и ошибка, архивы в
  хранилище, «Сделать бэкап сейчас».
- **Роботы** — создать (проект или `*`, чтение или запись, срок),
  перевыпустить секрет, удалить. Секрет — **один раз** окну браузера,
  или в `.env` конвейера, или сразу **ключом registry конвейера**
  (`env: @registry`: адрес — `RGSTR_PUBLIC`, логин — имя робота):
  конвейер потом сам качает свои образы из rgstr.
- **Политики** — хранения и неизменяемости: правка текстом JSON с диффом
  и историей в хабе, применить политику хранения сейчас.
- **Пользователи, вебхуки (проверка), журнал.**

**Команды сценариев:**

```
rgstr gc
rgstr retention run
rgstr tags shop/api
rgstr tag-delete shop/api 1.0
rgstr project shop quota 20
rgstr project dockerhub proxy https://registry-1.docker.io block critical
rgstr scan shop/api 1.0
rgstr backup run
rgstr robot ci-shop project shop push to-pipeline shop env @registry
```

**MCP:** `rgstr_summary`, `rgstr_repos`, `rgstr_tags`, `rgstr_projects`,
`rgstr_robots`, `rgstr_policies`, `rgstr_tag_delete`, `rgstr_gc_run`,
`rgstr_retention_run`, `rgstr_project_create`, `rgstr_robot_create`,
`rgstr_vulns`, `rgstr_scan_run`, `rgstr_backups`, `rgstr_backup_run`,
`rgstr_project_block`… —
агенту секрет робота отдаётся только в конвейер.

## Безопасность

- Плагин ходит в rgstr учётной записью администратора (Basic) — пароль
  только в `/etc/nkt-plugins/rgstr.env` (0600), не в журнале и не в
  ответах.
- Все имена (репозиторий, тег, проект, робот) проверяются до запроса;
  адрес upstream кеша — только `http(s)://хост[/путь]`, без логина в нём.
  Логин upstream плагин не принимает: он задаётся в `/ui` rgstr или в
  `RGSTR_PROXY_*`.
- Секрет робота rgstr показывает один раз; плагин его не хранит.
- Все изменения — с `dry_run` (сборка мусора и политика хранения в сухом
  прогоне спрашивают у rgstr, что было бы, ничего не удаляя).
