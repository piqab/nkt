# Почта: docker-mailserver

> **WARNING:** пример использует сторонний репозиторий и образы
> ([docker-mailserver](https://github.com/docker-mailserver/docker-mailserver)) —
> их безопасность и стабильность работы не гарантируются.

Почта на своём домене одним конвейером: Postfix (SMTP), Dovecot (IMAP),
Rspamd (спам и подпись DKIM), fail2ban. Без веб-почты и без своей базы —
ящики хранятся в файлах docker-mailserver.

- [`deploy/docker-compose.yml`](deploy/docker-compose.yml) — разовый
  `mail-init` (первый ящик `postmaster@MAIL_DOMAIN` из `.env`, если
  ящиков ещё нет) и `mailserver` (образ с закреплённой версией).
- [`pipeline.yaml`](pipeline.yaml) — конвейер: хост `mail1`, порты 25,
  465, 587, 993 — наружу на все адреса хоста.
- [`deploy/nkt-plugin.py`](deploy/nkt-plugin.py) — плагин хаба: ящики,
  алиасы, DKIM и записи DNS из «О системе» → «Плагины».

## Перед выкладкой

1. **Имя и адрес.** `MAIL_HOSTNAME` (например, `mail.example.com`) —
   A-запись на внешний адрес хоста. `MAIL_DOMAIN` — домен ящиков.
2. **Сертификат** для `MAIL_HOSTNAME` — «Сертификаты» хоста (certbot,
   `/etc/letsencrypt/live/MAIL_HOSTNAME`). Контейнер читает его только
   для чтения и сам подхватывает обновлённый.
3. **Порты.** 25 (приём почты), 465 и 587 (отправка клиентами), 993
   (IMAP) — открыть в файрволе хоста. Многие хостинги закрывают
   **исходящий 25** по умолчанию — без него письма наружу не уйдут;
   открывают по заявке.
4. **PTR** (обратная запись) внешнего адреса — на `MAIL_HOSTNAME`. Её
   ставит хостинг (панель или заявка), не DNS домена. Без PTR крупные
   почтовые службы отправляют письма в спам или отклоняют.
5. **Память.** Около 1 ГБ без антивируса; `ENABLE_CLAMAV: "1"` в `.env`
   — ещё около 1 ГБ.

## Выкладка

«Конвейеры» → «Примеры» → **Почта: docker-mailserver** → хост, имена,
домен. Пароль `postmaster` хаб создаст сам (`generate:password`) — он в
`.env` конвейера. `mail-init` заводит ящик только при первой выкладке:
сменить пароль потом — плагином.

## Плагин хаба

Своего API у docker-mailserver нет — плагин зовёт `setup` в контейнере
(`docker exec`), поэтому ставится **на хост почты** и ему нужен Docker
(служба в группе `docker` — это права root на хосте; хаб предупредит до
установки).

«О системе» → «Плагины» → **«Установить на хост»** → Почта
(docker-mailserver) → хост почты → `MAIL_HOSTNAME`, `MAIL_PUBLIC_IP`
(внешний IPv4: A-запись имени сервера и SPF; пусто — без A). Служба
`nkt-plugin-mail`, порт 9200 на 127.0.0.1.

- **Домены** — с числом ящиков и есть ли ключ DKIM. Домен появляется с
  первым ящиком.
- **Ящики** — добавить, сменить пароль, удалить. Пароль — только полем
  формы: он уходит в контейнер переменной окружения, не в командную
  строку и не в журналы. Хранится хешем.
- **Алиасы** — добавить и удалить.
- **Ключ DKIM** — «Создать ключ DKIM» (Rspamd, 2048 бит). После создания
  docker-mailserver нужно перезапустить («Хосты» → контейнер `mailserver`
  → «Перезапустить»), чтобы Rspamd начал подписывать.
- **Записи DNS** домена: MX, SPF, DKIM, DMARC и A (если задан
  `MAIL_PUBLIC_IP`). Кнопка **«Поставить через DNS-плагин»** — если к
  хабу подключён DNS-плагин (Technitium, Cloudflare): «Сверить»
  показывает, что изменится, «Применить» ставит. Хаб помнит, что
  поставил: чужие значения у тех же имён не трогаются, а убранная запись
  удаляется при следующем «Применить».
- **Сценарии:** `mail dkim ДОМЕН`, `mail alias add|rm АЛИАС КУДА`,
  `mail rm АДРЕС`, `mail records ДОМЕН` — без паролей. **MCP:**
  `mail_*`.

## Проверка

`python3 -I deploy/test_plugin.py` — плагин против поддельного `docker`
(без Docker); его же запускает `go test ./examples`. Проверяет, что
пароль не попадает в аргументы команды.
