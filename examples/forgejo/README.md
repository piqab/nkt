# Forgejo + PostgreSQL — веб через сайт, SSH наружу, без мастера установки

> **WARNING:** пример использует сторонний репозиторий и образы — их безопасность и стабильность работы не гарантируются. Проверьте их сами, прежде чем выкладывать в рабочую среду.

[Forgejo](https://forgejo.org) — git-сервер (сообщество, Codeberg). Своего
compose-файла для выкладки у проекта нет, поэтому он здесь:
[`deploy/docker-compose.yml`](deploy/docker-compose.yml) — Forgejo 16.0
(rootless-образ) и PostgreSQL 17, пароли и адреса — из `.env`.

**Два порта — два пути наружу:**
- веб (3000) — через сайт: блок `site:` публикует его на 127.0.0.1 и
  выпускает сертификат;
- SSH для `git clone ssh://git@…:2222/…` — встроенный сервер Forgejo на 2222,
  напрямую: `ports: forgejo: ["0.0.0.0:2222:2222"]` в конвейере. Без этой
  строки `bind` по умолчанию оставил бы SSH только на 127.0.0.1. **Откройте
  2222/tcp в файрволе хоста** (сайт открывает только 80/443).

**Без страницы установки.** Настройки задаются окружением
(`FORGEJO__…`, `INSTALL_LOCK=true`), регистрация закрыта. Администратора
заводит разовый сервис `forgejo-admin`: ждёт, пока Forgejo станет здоровым,
выполняет `forgejo admin user create --admin` с логином, паролем и почтой из
`.env` и завершается — nkt считает это успехом выкладки. Если такой
администратор уже есть, повторные выкладки его не трогают: пароль меняют в
самом Forgejo.

«Примеры» → «Forgejo + PostgreSQL», хост, имя в `site:`; значения `.env` —
в блоке `env:` `pipeline.yaml` (пароли создаст хаб; логин и почту
администратора поправьте). Пароль администратора — «Секреты» → «.env» →
история → «Показать». После выкладки — сразу вход администратором.

Данные Gitea в Forgejo 16 не переносятся: стек прежнего примера gitea
удалите (с томами) и выложите этот заново.

## Вариант через Traffic Fly

[`pipeline.fly.yaml`](pipeline.fly.yaml) — тот же стек, но вход через
VPS-шлюз (nkt-edge в роли fly) вместо прокси на хосте: маршрут `https` для
`git.example.com` (сертификат выпускает шлюз) и `tcp` 2222 для git по SSH.
Наружу на самом хосте ничего не открыто, A-запись — на адрес шлюза. Такой
стек удобно переносить между хостами: маршруты переключаются на новый хост
сами, DNS менять не нужно — пошагово в справке
[«Перенос стека с Traffic Fly»](https://piqab.github.io/nkt/guide/migrate-with-fly).

## Плагин хаба

Плагин `forgejo` управляет Forgejo (и Gitea — тот же API) прямо из хаба.
Написан по [руководству для агентов](../AGENTS.md) из
[заготовки](../_template).

- **Сводка и находки:** версия, число репозиториев, пользователей и
  администраторов; упавший последний запуск Actions, зеркало без
  синхронизации больше 7 дней, больше трёх администраторов.
- **Репозитории:** создать (у себя или в организации), в архив,
  синхронизировать зеркало, удалить — с подтверждением; запуски Actions и
  вебхуки репозитория.
- **Вебхуки:** добавить — например, вебхук выкладки конвейера nkt
  («Выкладки» → конвейер → «Вебхук»), удалить.
- **Пользователи:** администраторы, последний вход, блокировка.
- **Токен регистрации раннера** — для всего экземпляра или одного
  репозитория: окну хаба один раз, агенту и сценарию — только сразу в
  `.env` конвейера (например, конвейера раннера `forgejo-runner`).
- **Сценарии:** `forgejo repos`, `forgejo mirror-sync ВЛАДЕЛЕЦ/РЕПО`,
  `forgejo archive ВЛАДЕЛЕЦ/РЕПО`, `forgejo hook add ВЛАДЕЛЕЦ/РЕПО АДРЕС`,
  `forgejo runner-token [ВЛАДЕЛЕЦ/РЕПО] to-pipeline КОНВЕЙЕР env ИМЯ`.
  **MCP:** `forgejo_*`.

**Поставить:** «О системе» → «Плагины» → «Каталог» → Forgejo →
«Установить на хост» (хост Forgejo — тогда адрес `http://127.0.0.1:3000`).
Токен: в Forgejo администратором → «Настройки» → «Приложения» →
«Сгенерировать токен», права `admin`, `repository`, `user`,
`organization` (чтение и запись). Токен хранится только в файле настроек
службы (`0600`), в журнал и ответы не попадает.

В API Forgejo нет состояния 2FA пользователей и настройки открытой
регистрации — таких находок у плагина нет. Проверено на поддельном API
(`python3 -I deploy/test_plugin.py`), не на живом Forgejo.
