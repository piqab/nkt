# Тестовый хаб nkt

Второй хаб в Docker рядом с рабочим — пробовать новые версии, импорт,
настройки, не рискуя рабочим. Выкладывается конвейером рабочего хаба на
его же машину (`localhost`).

## 1. Выложить

«Выкладки» → «Новый конвейер» → **«Примеры» → «Тестовый хаб nkt»**, хост
**localhost** — описание готово: образ той же версии, что рабочий хаб,
порты `127.0.0.1:18443` и `18446`, пароль администратора создаст хаб.
Или вставьте [`pipeline.yaml`](pipeline.yaml). «Сухой прогон», затем
«Выложить».

Вход:

- на самой машине — `http://127.0.0.1:18443`;
- со своего компьютера — `ssh -L 18443:127.0.0.1:18443 <машина хаба>`,
  затем `http://127.0.0.1:18443`;
- с HTTPS — раскомментируйте `site:` (имя и A-запись на машину хаба).

Пользователь `admin`, пароль — «Секреты» → «.env» → «Показать»
(`NKT_BOOTSTRAP_ADMIN_PASSWORD`; применяется при первом запуске, пока база
пуста).

## 2. Не управляйте теми же хостами

Два хаба над одними хостами мешают друг другу: выкладки по опросу идут из
обоих, «Применить» Traffic Fly в одном перезаписывает шлюзы другого,
обновления nkt, смена ключа узкого sudo отрежет другой хаб.

- **Полный экспорт рабочего в тестовый не импортируйте.** Нужны данные —
  в плане импорта пропустите хосты, конвейеры, маршруты Traffic Fly и
  nkt-edge.
- Заведите тестовые хосты: VM, LXD-контейнер, запасной VPS.
- Хост, к которому ходят оба хаба, в «Хостах» помечен значком «ещё один
  хаб» — уберите его из одного из них.

## 3. Что учесть

- `localhost` тестового хаба — его контейнер: выкладывать и переносить
  «на машину хаба» он не может (в контейнере нет Docker).
- Обновление — правкой тега в `images:` и выкладкой из рабочего хаба.
  Кнопка «Обновить» в «О системе» тестового хаба контейнер не обновит.
- Хаб в контейнере не выкладывает и не переносит стек, в котором работает
  сам, — отказ с объяснением.
- Удаление — удалением конвейера; с галочкой «и тома» уйдут база и ключ
  шифрования тестового хаба.

## Если не выкладывается

**«Нет доступа к образу»** — образ `ghcr.io/piqab/nkt-hub` этой версии
недоступен без входа: ещё не выпущен или пакет в GitHub закрыт (новые
пакеты GitHub по умолчанию приватные). Владелец репозитория открывает его
один раз: GitHub → Packages → `nkt-hub` → Package settings → Change
visibility → Public. До того — ключ с правом `read:packages` в «Секреты» →
«Реестры» конвейера (`ghcr.io`).
