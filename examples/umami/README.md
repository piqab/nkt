# umami — несколько сервисов и секреты из .env

[umami](https://umami.is) — веб-аналитика: приложение и PostgreSQL. Пример
показывает стек из двух сервисов из **чужого** репозитория без форка:
compose-файл берётся из
[umami-software/umami](https://github.com/umami-software/umami/blob/master/docker-compose.yml)
как есть, а nkt меняет в копии, которая едет на хост, то, что нужно.

## Что в compose-файле umami и что делает nkt

| В файле | nkt |
|---|---|
| `APP_SECRET: replace-me…`, `TWO_FACTOR_ENCRYPTION_KEY`, пароль БД `umami` — значениями | `env_keys` — эти переменные берутся из `.env` конвейера (зашифрован на хабе, на хосте 0600); файл в репозитории не меняется |
| `ports: "3000:3000"` — на всех адресах | `bind` по умолчанию: `127.0.0.1:3000:3000`, наружу — только через прокси сайта |
| healthcheck у обоих сервисов | `up --wait` ждёт, пока база и umami станут healthy |
| том `umami-db-data` | данные базы; удаление конвейера без галочки «тома» его сохраняет |

## 1. Конвейер

«Выкладки» → «Новый конвейер» → **«Примеры» → «umami + PostgreSQL»**,
выберите хост — описание готово (или вставьте `pipeline.yaml`, поправив
`hosts` и `domains`). Сохраните.

## 2. .env стека

«Доступ» конвейера → **«.env стека»**:

```
APP_SECRET=<openssl rand -hex 32>
TWO_FACTOR_ENCRYPTION_KEY=<openssl rand -hex 32>
POSTGRES_PASSWORD=<пароль базы>
DATABASE_URL=postgresql://umami:<пароль базы>@db:5432/umami
```

Пароль в `POSTGRES_PASSWORD` и в `DATABASE_URL` — один и тот же. Без
любой из переменных выкладка не начнётся (сухой прогон назовёт, каких нет).

## 3. Выкладка и сайт

«Сухой прогон» → «Выложить». Первый старт — около минуты (миграции).
Блок `site:` — сайт с сертификатом на вашем имени (A-запись → хост),
прокси смотрит на `127.0.0.1:3000`. Вход в umami — `admin` / `umami`:
**сразу смените пароль** в настройках umami.

Проверено: выкладка на docker 29 — оба сервиса healthy за ~80 секунд,
`/api/heartbeat` отвечает.

## Версия

Файл umami ссылается на `ghcr.io/umami-software/umami:latest` — каждая
выкладка берёт свежий образ. Закрепить версию — `images:` в конвейере
(`umami: ghcr.io/umami-software/umami:<версия>`).

## Удаление

«Удалить» конвейер: контейнеры и сеть убираются, каталог стека
переносится в `.nkt-removed`, том с базой остаётся (галочка «тома» —
удалить и его).
