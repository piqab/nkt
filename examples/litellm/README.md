# LiteLLM

> **WARNING:** пример использует сторонний репозиторий и образы
> ([LiteLLM](https://github.com/BerriAI/litellm)) — их безопасность и
> стабильность работы не гарантируются.

Один OpenAI-совместимый адрес перед любыми моделями — своими (llama.cpp,
Ollama, vLLM) и облачными (OpenAI, Anthropic…) — с **виртуальными
ключами**: у каждого ключа свои модели, бюджет, лимиты запросов и токенов,
срок, расход. Приложение получает свой ключ, а не ключ провайдера.

- [`deploy/docker-compose.yml`](deploy/docker-compose.yml) — LiteLLM
  (версия образа закреплена) и PostgreSQL для ключей, моделей и расхода.
- [`pipeline.yaml`](pipeline.yaml) — конвейер: хост `llm1`, сайт с HTTPS
  для API.
- [`deploy/nkt-plugin.py`](deploy/nkt-plugin.py) — плагин хаба: ключи,
  модели, расход из «О системе» → «Плагины».

## Выкладка

«Конвейеры» → «Примеры» → **LiteLLM** → хост, домен API. Хаб сам создаст:

- `LITELLM_MASTER_KEY` — мастер-ключ (у LiteLLM он `sk-` + это значение);
- `LITELLM_SALT_KEY` — ключ, которым LiteLLM шифрует ключи провайдеров в
  базе. **Не меняйте его после первой выкладки** — сохранённые ключи
  провайдеров станут нечитаемыми;
- `LITELLM_DB_PASSWORD` — пароль базы.

Своя админка LiteLLM (`/ui`) выключена: ключи и модели ведёт плагин хаба.
Включить — `LITELLM_DISABLE_ADMIN_UI: "False"` в `env` конвейера (вход —
мастер-ключом).

Прокси хаба ждёт ответа до 5 минут; потоковые ответы (`stream: true`)
идут сразу, без буферизации.

## Плагин хаба

«О системе» → «Плагины» → **«Установить на хост»** → LiteLLM → хост, где
выложен LiteLLM → мастер-ключ (из `.env` конвейера; `sk-` плагин добавит
сам). Служба `nkt-plugin-litellm`, 127.0.0.1:9210, без Docker.

- **Модели** — «Добавить модель»: имя для клиентов (`qwen`), модель
  провайдера (`openai/qwen3-8b` — любая OpenAI-совместимая: llama.cpp,
  Ollama, vLLM; `anthropic/claude-sonnet-4-5`, `openai/gpt-4o`), адрес API
  и ключ провайдера (скрытое поле; LiteLLM хранит его зашифрованным).
  Удаляются модели, добавленные так; модели из файла настроек — нет.
- **Ключи** — «Создать ключ»: имя, модели (пусто — все), бюджет в
  долларах и когда он обнуляется, лимиты запросов и токенов в минуту, срок.
  - **В окне** новый ключ показывается **один раз** с кнопкой
    «Скопировать» — ни хаб, ни плагин его больше не покажут.
  - **Сразу в `.env` конвейера** — поля «Сразу в .env конвейера» и «Имя
    переменной» (`LLM_API_KEY`): ключ не показывается, хаб записывает его
    в `.env` конвейера приложения (с историей версий), в стек он придёт
    со следующей выкладкой.
  - «Заблокировать» / «Разблокировать», «Удалить».
- **Расход** — по ключам и всего, с создания ключа, по ценам LiteLLM (у
  своих моделей цена 0).
- **Сценарии** — `llm keys`, `llm key block|unblock|rm ИМЯ`, новый ключ
  только сразу в `.env`:
  `llm key add videolog models qwen budget 20 budget-reset 30d to-pipeline videolog env LLM_API_KEY`.
- **MCP** — `litellm_*`. Агент создаёт ключ только с `to_pipeline` и
  `env` — значение он не увидит.

Права: смотреть — всем, менять — администратору или токену с действием
«плагин litellm»; записать ключ в `.env` конвейера — ещё и право править
этот конвейер (администратор или токен с «pipeline.create» в своих
пределах).

## Приложение

```
OPENAI_BASE_URL=https://llm.example.com/v1
OPENAI_API_KEY=${LLM_API_KEY}
```

Модель — по имени для клиентов: `"model": "qwen"`.

## Проверка

`python3 -I deploy/test_plugin.py` — плагин против поддельного API
LiteLLM (без Docker); его же запускает `go test ./examples`. Проверяет, в
том числе, что ключи не попадают в журнал службы.
